# S06/S10 durable implementation and verification

Checked 2026-10-10. Local implementation supports the bounded Snapp and existing Okala feed seams. Production durable enablement remains gated. The feed retains its server-selected policy with no category browsing, campaign selection, arbitrary provider URL, credential input or wider collection adapter.

## Implemented phases

1. **Reserve and reconcile:** additive migration 0007 records tenant UUID intents, request fingerprints, dispatch intent, deterministic instance ID, scan-owned device UUID, elapsed deadline and attempt limits. A D1 batch reserves scan/metadata/key together. The account active-scan constraint and atomic global workflow admission guard enforce deployment capacity (default one). Repeated identical starts return the normalized record; changed input with the same key returns 409. Legacy execution also claims a key once when the durable flag is disabled. Okala uses `max(30, requestedThreshold)` consistently.
2. **Plan and fetch pages:** Workflow payload contains only scan ID and contract version. D1 supplies the frozen tenant/location/manifest. Discovery requests checkpoint separately and actual selected units freeze before enumeration. Snapp baseline and supported store campaigns fetch one real page per request. Existing Okala discovery/campaign units use the same durable seam. Unverified Okala next-page contracts fail closed. Guest access remains ephemeral; replay reacquires it with the persisted device UUID. A persisted compare-and-set allows one 401 refresh for the entire scan, so an ephemeral resume cannot reset that allowance.
3. **Stage and publish:** page content digests and 20-row chunks with atomic chunk receipts support interruption/replay without inflated counts. A complete receipt requires all intended chunks. Migration 0008's saved projection materializes before a final guarded publication batch checks all frozen units terminal, no incomplete page, no cancellation, and projection readiness. It publishes scan coverage/status and the final observed timestamp. Public legacy deals and product reads hide running/failed/cancelled staging.
4. **Recover and operate:** cancellation persists a compare-and-set before best-effort engine termination. Subsequent writes reject terminal work. Same-instance reconciliation handles lost create responses and never recreates terminal scans. Engine transport errors remain uncertain. The legacy stale timer excludes durable jobs. Scheduled reconciliation examines at most 20 active jobs; cleanup removes at most 20 failed/cancelled staging sets older than seven days, preserving history/start keys and completed results. New tables cascade with location-history deletion.
5. **Measure enrichment:** `readDurableComparison(db,userId,scanId)` returns private committed-page facts: baseline eligible identities, per-campaign qualifying identities, raw/unique counts, baseline overlap, actual additions to the accumulated union, excluded reason counts and aggregate additions. Exact duplicates collapse; signatures include excluded rows to detect cross-page price/stock/title/benefit conflicts. Reports distinguish zero eligible rows from eligible rows already in the union. Completion requires published succeeded coverage. No customer field or control is introduced.

## Bounds and retry ownership

Execution is sequential. Durable guards are 15 minutes elapsed from reservation, 250 physical outbound attempts including guest access, 100 collected pages and 10,000 unique eligible offers. Enabled Snapp enrichment retains the stricter existing 40-attempt envelope: at most two dynamically discovered supported collections, at most 700 raw rows/eight responses each, with baseline/retry reserves. Limits fail incompletely and never establish exhaustion.

Physical requests reserve capacity in D1 before sending. Effect makes one attempt; the Workflow reader owns at most three total attempts per logical GET for network/timeout/408/429/5xx. Native step retries handle persistence defects without multiplying provider attempts. Retry-After stays within the persisted deadline. Malformed schemas, ownership conflicts, count drift and cancellation do not retry. Redirects are manual and rejected by status. A crash can conservatively overcount, and replay cannot reset limits. Bounded private D1 provider checkpoints exclude guest responses/tokens; Workflow output contains only small metadata.

Campaign terminal evidence requires stable reported **raw** row count plus an empty page. Exact repeated identities are valid (raw four / unique three); conflicting facts fail incompletely. Baseline uses its verified vendor-total boundary. The latest successfully observed complete money, stock, and benefit tuple wins on overlap; equal-time ties use stable adapter priority and feed identity. Provenance is merged and price conflicts are recorded privately. Stored response observation times survive replay. Operational logs include scan/unit identifiers, request reservations, page/count/terminal facts, staging duration and typed completion/failure; they omit credentials, customer IDs and coordinates.
